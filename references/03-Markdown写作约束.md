# 03 Markdown 写作约束（md2docx 转换支持子集）

## 适用范围

本文件面向「用 Markdown 撰写、再经 `scripts/md2docx.py` 转为 Word」的中文课程设计文档、技术文档作者与 AI 代理，说明转换脚本认识哪些写法、忽略哪些写法、误处理哪些写法，以及因此必须遵守的写作习惯。

本文件只约束源文件 `.md` 的写法。成品 Word 的字体、字号、行距、缩进、三线表线宽、页面参数，见 [02-Word格式规范.md](02-Word格式规范.md)；图表制作流程与命名，见 [04-图表与表格规范.md](04-图表与表格规范.md)。

一句话原则：脚本是逐行正则解析的小转换器，不是完整的 Markdown 解析器。**源文件只写本文列出的支持写法，未列出的写法一律视为不安全。**

## 一、转换器的工作方式

- 脚本逐行读取源文件，用正则判断该行是标题、列表、表格、图片还是普通段落，再写入 Word。
- 每个非空行就是一个段落；空行被跳过，不产生空段落。
- 无法识别的行不会报错，而是原样当普通段落输出，所以残留的语法符号会出现在成品里。
- 脚本会设置的成品要素：页面（默认 A4、页边距）、字体字号、段落行距与缩进、页眉、页脚页码。封面、目录与 PDF 导出仍由作者在 Word 中手工完成（见 02-Word格式规范.md）。
- 会中断转换的情况：表格中某一行的单元格数多于表头列数（写表时索引越界）；图片文件损坏无法读取。列数不一致时脚本先打印告警，随后仍可能在写表时中断，所以必须保证每行列数一致。

| 后果类别 | 表现 | 典型写法 |
| --- | --- | --- |
| 正常支持 | 按预期排版 | 三级标题、段落、管道表格、列表、加粗、图片、表注 |
| 静默降级 | 转换「成功」，但符号原样当文字输出或层级丢失，无任何提示 | 链接、行内代码、斜体、删除线、HTML 标签、脚注 |
| 告警后降级 | 转换「成功」并打印一次告警，符号被去掉但外观丢失 | 代码块、四级标题、引用块、任务列表 |
| 静默丢失 | 内容不进入成品 | 分隔线、空行、缺失的图片及其图注 |
| 转换失败 | 脚本抛异常退出，不生成 docx | 表格某行单元格数多于表头 |

## 二、支持的语法

| 语法 | 源文件写法 | 转换结果 | 注意事项 |
| --- | --- | --- | --- |
| 一级标题 | `# 文档名` | Heading 1，黑体三号，无缩进 | `#` 后必须是半角空格；全文只用一次，放在第一行 |
| 二级标题 | `## 一、引言` | Heading 2，黑体小三 | 章节标题，编号手工写 |
| 三级标题 | `### 1.1 编写目的` | Heading 3，黑体小四并整行加粗 | 小节标题，编号手工写 |
| 正文段落 | 一段文字写在同一个源文件行 | 宋体小四，两端对齐，首行缩进 2 字符，固定 22 磅行距 | 一段一行，不要手动折行 |
| 无序列表 | `- 条目内容` | Word 项目符号列表，无首行缩进 | 符号是半角减号加一个空格 |
| 有序列表 | `1. 步骤内容` | Word 自动编号列表 | 源文件里的数字被丢弃，编号由 Word 重排 |
| 行内加粗 | `**表 2-1 系统五层组成**` | 该段内文字加粗，其余部分不变 | 成对使用；不能跨段落 |
| 管道表格 | 表头行、分隔行（竖线与短横组成）、数据行 | 三线表，表头加粗并跨页重复 | 首行为表头，第二行必须是分隔行 |
| 表注 | 表格上方一行 `**表 2-1 系统五层组成**` | 宋体小五、居中，位于表格上方 | 必须位于表格上方，与表头之间可隔空行（脚本会跳过空行确认下方是表格），但不得隔着正文段落 |
| 图片与图注 | `![图 2-1 系统五层组成方框图](images/fig2-1.png)` | 图片居中嵌入，宽度最大 14.5cm，图注在图片下方居中 | 必须独占一行，一行只放一张图 |
| 图片无图注 | `![](images/fig2-1.png)` | 只插图片，不生成图注 | 正式文档不要这样写，图必须带图注 |
| 空行 | 空行 | 忽略，不产生任何内容 | 只用于分隔源文件段落 |
| 分隔线 | `---` | 忽略，不生成横线 | 只作源文件可读性标记 |

### 2.1 表格的识别规则

- 表格由连续的、以竖线开头的行组成；遇到第一行不以竖线开头的内容即结束。
- 第一行是表头，第二行必须是分隔行（形如 `| --- | --- | --- |`），否则这一块不会变成表格，而是带竖线的普通段落。
- 表格中间不能有空行；空行会把表格截断，后半段变成不规范内容。
- 表格后紧跟以竖线开头的正文行，会被并入表格，多出多余的一行。
- 每行单元格数必须与表头完全一致：多于表头会让脚本报错退出；少于表头时该行末尾留空单元格，不报错但排版不整齐。
- 分隔行里的对齐标记（如 `:---:`）被忽略，脚本没有列对齐与列宽控制，表格均匀分列。
- 单元格首尾空格会被去掉；单元格内的加粗按行内加粗处理。

### 2.2 图片的识别规则

- 图片语法必须独占一行，正则匹配整行；行内混写文字会导致图片不插入、文字照常当段落输出。
- 方括号里的文字就是图注（alt），不能为空，否则图片下方没有图注。
- 路径按 md 文件所在目录解析，因此统一写相对路径 `images/figX-Y.png`，用正斜杠，不要写绝对路径。
- 图片文件必须真实存在：缺失时脚本打印「警告: 图片不存在，已跳过: <路径>」，跳过该图与图注后继续转换，成品里会少图且不易察觉；`check_md.py` 会把缺失图片报为错误。
- 路径里可以有空格（如 `images/fig4-1 系统总体 ER 图.png`，本项目实际存在此类文件，脚本按完整路径读取），但推荐统一用纯编号 `figX-Y.png`；不要加引号或标题参数，`![说明](path "title")` 会把引号与 title 当作文件名的一部分而找不到文件。
- 脚本不放大图片：宽度大于 14.5cm 的图按 14.5cm 排版，小于 14.5cm 的按原始宽度排版。

## 三、禁用语法清单

下表每一种写法都要避免。转换后果来自对脚本的逐行确认与实际转换测试。

| 写法 | 转换后果 | 替代写法 |
| --- | --- | --- |
| 代码块（三个反引号围栏） | 围栏行本身不输出；块内每一行按普通正文段落原样输出（块内不再解析 Markdown，`#` 与 `-` 只作为文字），缩进与等宽字体丢失，脚本告警一次 | 用表格或列表描述逻辑；确需代码示例，转换后到 Word 里手工插入，且不再重新生成该 docx |
| 链接 `[文字](链接地址)` | 方括号与地址原样作为文字输出，没有超链接 | 写「见 3.2 节」或「见参考资料 [3]」，URL 只放在文末参考资料列表的纯文本行里 |
| 嵌套列表（缩进的子项） | 子项被当成同级项，层级信息丢失 | 用表格分列表达层级；或把子项写成「（1）（2）」接在父项同一段内 |
| 四级标题 `#### 标题` | 去掉 `#### ` 前缀后按整段加粗的正文输出，脚本告警一次；没有标题样式，也不进目录 | 用独立一段 `**4.1.1 实体与联系**` 表示四级标题 |
| 引用 `> 文字` | 去掉 `>` 前缀后按普通正文段落输出，脚本告警一次；引用的层级外观丢失 | 改成普通段落，或写「注：……」 |
| HTML 标签（`<br>`、`<b>`、`&nbsp;`） | 标签原样显示为文字，`<br>` 不会变成换行 | 拆成多个自然段；去掉所有标签 |
| 行内代码（反引号包围） | 反引号原样出现在成品里，没有等宽字体 | 去掉反引号直接写文字，必要时用加粗强调 |
| 斜体 `*文字*` 或 `_文字_` | 星号或下划线原样保留 | 用 `**加粗**`，或直接不强调 |
| 删除线 `~~文字~~` | 两个波浪号原样保留 | 不要的内容直接删掉；需保留痕迹时写「（已废止）」 |
| 任务列表 `- [ ] 事项` | 方括号标记被去掉，退化为普通项目符号项（`[x]` 同样被去掉），未完成/已完成的区别丢失 | 用表格加「状态」「负责人」列表示进度 |
| 单元格内换行 | 回车会截断表格；`<br>` 会当文字输出，表格被截断或串行 | 一条内容写成一行；多条内容拆成多行表格，或在单元格里用分号、顿号分隔 |
| 合并单元格 | 脚本无法表达跨行跨列；靠多写竖线凑列还会导致该行单元格数超过表头，直接转换失败 | 重复填写相同内容，或写「同上」「见上表」，必要时拆成两张表 |
| 单元格内竖线 | 竖线被当成分列符，该行单元格数超过表头时转换失败 | 用顿号、斜杠、分号或全角竖线代替 |
| 在 md 里写封面块 | 封面文字变成正文段落，挤在文档开头，且与在 Word 中排的封面重复 | 封面只在 Word 里手工排版，md 从文档标题开始写 |
| 在 md 里写目录 | 只有一行行文字，没有真正的目录域 | 目录在 Word 中用「引用—目录」插入并更新域 |
| 脚注 `[^1]` 与脚注定义行 | 引用标记与定义行都变成正文文字 | 用括注「（作者，年份）」；正式引用统一列参考文献表 |
| YAML front matter | 起始的两条分隔线被丢弃，`title: ……` 变成正文段落 | 不写 front matter，元信息写进正文或交付说明 |
| 井号后缺空格（`#标题`） | 整行按正文输出，井号保留 | 井号后补一个半角空格 |
| 一段写成多行（段内硬换行） | 每行变成独立段落，各自首行缩进 2 字符，行距被撑开 | 一段只写一行，折行交给 Word |
| 行首缩进空格 | 空格被保留，与首行缩进叠加，出现参差 | 行首不写空格 |
| UTF-8 带 BOM 保存 | 第一行（通常是文档标题）识别失败，变成带不可见字符的正文段落 | 用 UTF-8 无 BOM 保存，改完首行务必确认它是标题 |

说明：本文与 04 中的代码块只用于展示模板与命令，仅限 references 参考文档；被转换的目标 md 禁止出现代码块。

## 四、写作规则

### 4.1 标题层级与编号

- 只用三级标题：`#` 文档名，`## 一、引言`，`### 1.1 编写目的`，与 02-Word格式规范.md 的字体约定一一对应。
- 编号一律手工写在标题文字里，脚本不会自动编号，也不会修正跳号。章节用中文数字（一、二、三），小节用阿拉伯数字（1.1、1.2），全文统一。
- 四级以内用 `### 1.1`，五级内容用独立一段 `**1.1.1 标题**`，不要用 `####`。
- 标题里不要用加粗标记：一级、二级标题内的 `**` 会被忽略且不产生加粗，白写还容易误导。
- 同一层级的标题格式要一致，不要在同一章里混用「1.1 目的」与「（一）目的」。

### 4.2 段落

- 一段一行，长段自然折行，由 Word 承担排版；源文件里手动换行会变成多个段落。
- 段落之间用一个空行分隔，便于阅读源文件；空行本身不会进入成品，不要靠空行制造间距。
- 首行缩进由脚本统一施加，不要在行首加空格或全角空格。

### 4.3 标点与字符

| 内容 | 规则 | 示例 |
| --- | --- | --- |
| 中文标点 | 全角 | 逗号、句号、顿号、括号、引号 |
| 数字 | 半角 | 2026、14、3.18 |
| 英文单词与缩写 | 半角，与中文之间不强制空格 | Word、Spring Boot、Neo4j |
| 单位 | 半角数字加半角单位，单位与数字之间不空格 | 14.5cm、22 磅写成 22pt |
| 范围与编号 | 用半角连字符，前后不加空格 | 图 4-1、表 2-3、F01-F10 |

### 4.4 表格写法模板

```markdown
**表 4-1 实体与关联表清单**

| 序号 | 表名 | 说明 |
| --- | --- | --- |
| 1 | user | 用户表 |
| 2 | patient_profile | 慢病档案表 |
```

- 表注与表头之间可以空一行（脚本会跳过空行、确认下方是表格后渲染为表注），但中间不能插入正文段落；紧贴表头写最稳妥。
- 每行单元格数与表头一致，不要把长句塞进单元格，超过一行的内容改成正文说明。

### 4.5 图注与图片

```markdown
![图 2-1 系统五层组成方框图](images/fig2-1.png)
```

- 图注文字以「图 x-x 」开头，后接图名；编号规则与文件命名见 04-图表与表格规范.md。
- 图片路径相对 md 所在目录，统一放该文档目录下的 `images/`，文件名用 `figX-Y.png`。
- 图片前后各留一个空行，避免与正文段落粘连。

### 4.6 列表与表格的取舍

| 内容特征 | 推荐写法 | 理由 |
| --- | --- | --- |
| 并列的参数、字段、职责、对照项 | 表格 | 列对齐后便于横向比较，一行一个对象 |
| 操作步骤、处理流程 | 有序列表 | 编号由 Word 生成，增删步骤不必改号 |
| 注意事项、约束、要点 | 无序列表 | 条目短、无先后关系 |
| 需要多级层次的内容 | 表格拆列 | 嵌套列表在转换中会丢层级 |
| 单个长句说明 | 普通段落 | 表格里塞长句会撑高行 |

## 五、转换前自检清单

- [ ] 文件保存为 UTF-8 无 BOM，第一行是 `# 文档名`
- [ ] 只用 `#`、`##`、`###` 三级标题，无 `####`
- [ ] 所有标题编号手工写全，无跳号、无重号
- [ ] 每个自然段在源文件中只占一行
- [ ] 无代码块、无反引号、无斜体、无删除线、无引用符号、无 HTML 标签
- [ ] 无行内链接，URL 只出现在参考资料纯文本行
- [ ] 无嵌套列表、无任务列表、无多级缩进
- [ ] 每张表都有位于表格上方的表注行（可紧邻表头或隔一空行），表注行内没有别的星号
- [ ] 表格每行单元格数与表头完全一致，单元格内无竖线、无换行
- [ ] 每张图独占一行，方括号内图注非空且以「图 x-x 」开头
- [ ] 所有图片文件存在，路径为相对路径且用正斜杠
- [ ] 全文中文全角标点、数字英文半角
- [ ] md 中没有封面块与目录块
- [ ] 转换前运行 `python scripts/check_md.py` 无 ERROR，转换后再运行 `python scripts/check_docx.py` 无 ERROR（用法见 05-工具链与环境.md）
- [ ] 转换命令执行无报错，转换后核对图片数与表格数（见 04-图表与表格规范.md）
