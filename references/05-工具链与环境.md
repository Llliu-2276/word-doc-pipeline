# 05 工具链与环境

适用范围：使用本 Skill 把 Markdown 批量转换为 Word（.docx）并导出 PDF 的**环境搭建、命令执行、成品核查与迁移**。读者为执行转换的作者或代理。本文命令均在**项目根目录**执行；路径含中文或空格时一律加引号。文中"本机"指 2026-11-10 的实测环境（Windows + Python 3.12.10 + python-docx 1.2.0）。

## 一、环境要求

| 组件 | 实测版本 | 用途 | 缺失后果 |
| --- | --- | --- | --- |
| Python | 3.12.10 | 运行全部转换/校验脚本 | 无法转换 |
| python-docx | 1.2.0 | 生成与读取 .docx | `import docx` 直接失败 |
| Microsoft Word | 建议 2016 及以上 | 补封面、插目录、更新域、另存 PDF | 无法产出最终 PDF |
| pdftotext | 可用（MSYS2 ucrt64，已在 PATH） | 抽取 PDF 首页文本做核对 | 需改用 Word 目检 |
| 中文字体 | 宋体、黑体、Times New Roman | 还原规范字体 | 渲染回退，版式变形 |
| pdfinfo | **未安装** | 官方查页数/页面尺寸 | 改用本文的 Python 正则命令 |

说明：本机没有 `py` 启动器，统一用 `python`；`pdfinfo` 缺失是本机既定事实，不要写依赖它的命令。

## 二、安装与自检

```powershell
# 安装/升级依赖（首次转换前执行一次）
python -m pip install python-docx

# 自检：Python 与 python-docx 版本
python --version
python -c "import docx; print(docx.__version__)"
```

预期输出 `Python 3.12.10` 与 `1.2.0`。若第二条报 `ModuleNotFoundError: No module named 'docx'`，先装依赖再转换——转换脚本会在 `import docx` 处直接中断，不会给出友好提示。

## 三、脚本接口

五个脚本位于项目的 `scripts/` 目录（本 Skill 源目录为 `word-doc-pipeline/scripts/`，迁移后复制到目标项目根目录 `scripts/`，`profiles/` 一并复制）。下表参数即唯一契约，不要自行发明参数。

| 脚本 | 用途 | 调用方式 | 退出码 |
| --- | --- | --- | --- |
| `profile.py` | 查看/校验排版参数 profile | `python scripts/profile.py --list \| --show <名> \| --check <名>` | `--check` 不通过时非 0 |
| `md2docx.py` | 单个 md 转 docx | `python scripts/md2docx.py <输入.md> <输出.docx> [--profile 名] [--toc\|--no-toc] [--project "页眉项目名"] [--no-header] [--no-footer] [--page-size A4\|Letter]` | 0 成功；非 0 失败 |
| `check_md.py` | md 静态检查：禁用语法、图片缺失、图注/表注格式、编号连续性 | `python scripts/check_md.py <md文件或目录>... [--profile 名] [--all]` | 非 0 表示有错误 |
| `check_docx.py` | docx 合规检查：按 profile 期望值核对页面、边距、页眉页码、图片宽度、表格、字体行距、目录域 | `python scripts/check_docx.py <docx文件或目录>... [--profile 名] [--project "页眉项目名"]` | 非 0 表示不合规 |
| `build_docs.py` | 批量转换 + 校验并汇总 | `python scripts/build_docs.py <docs目录> [--profile 名] [--toc\|--no-toc] [--project "页眉项目名"] [--include 模式]` | 非 0 表示有失败项 |

`--profile` 省略时用默认 profile `ug-thesis-bit`；可用值由 `profiles/` 下的 `.toml` 文件名决定（`tech-doc` 等）。**转换与校验必须用同一个 profile**，否则校验报出的差异来自两份 profile 不一致，而不是文档本身。

```powershell
# 看有哪些 profile、某个 profile 展开成什么、能不能通过校验
python scripts/profile.py --list
python scripts/profile.py --show tech-doc
python scripts/profile.py --check tech-doc

# 单篇：md -> docx（默认 profile；页眉项目名按实际项目替换）
python scripts/md2docx.py "docs/功能分析说明书/功能分析说明书.md" "docs/功能分析说明书/功能分析说明书.docx" --project "ChronoMed-Safe 慢病智能用药管理与风险预警系统"

# 换文档类型：技术文档版式（1.5 倍行距、图表名五号黑体、首页不编页码），并生成目录前置节
python scripts/md2docx.py "docs/技术文档/接口说明.md" "docs/技术文档/接口说明.docx" --profile tech-doc --toc --project "某系统"

# 先查 md，再转 docx，再查 docx（三处 profile 保持一致）
python scripts/check_md.py "docs/功能分析说明书/功能分析说明书.md"
python scripts/check_docx.py "docs/功能分析说明书/功能分析说明书.docx" --project "ChronoMed-Safe 慢病智能用药管理与风险预警系统"

# 批量：转换 docs 下全部文档并汇总（可用 --include 限定文档类型）
python scripts/build_docs.py docs --project "ChronoMed-Safe 慢病智能用药管理与风险预警系统"
```

要点：

- `check_md.py` / `check_docx.py` 接受多个路径，可直接传目录；
- 两条 check 命令的退出码是 CI/脚本可用的唯一信号，**不要靠人工读日志判断通过**；
- `md2docx.py` 的纸张与边距来自 profile 的 `[page]` 段（默认 A4），`--page-size` 是临时覆盖，正式交付不要用 Letter；`--no-footer` 仅用于特殊文档，正常不要关页脚页码；`build_docs.py` 的 `--include` 是 md 文件名匹配模式（如 `--include 选题报告`），正式批量重建前先加 `--dry-run` 确认范围；
- 图片路径按 md 文件所在目录解析，md 中统一写 `images/figX-Y.png`；md 源文件须保存为 UTF-8（无 BOM），否则中文与符号可能乱码。注意 `profile.py` 自己的 `_read_toml` 用 `utf-8-sig` 读 profile，能容忍 BOM，但 md 不能。

## 四、Word 手工步骤（脚本不覆盖）

封面与目录不经脚本（`--toc` 可代劳目录域，但封面永远手工），每次重出 docx 后都必须重做：

1. 用 Word 打开刚生成的 docx。
2. **补封面**：按课程/项目模板排版（校名、文档名、信息表、日期）；本项目的封面底版见 `docs/封面.docx`，可直接复制页面内容后改文字。
3. **插入目录**：转 docx 时加过 `--toc`（或 profile 写了 `structure.toc = true`）时，「目录」前置页与 TOC 域已存在，直接跳到第 4 步；否则用 引用 → 目录 → 自动目录（1~3 级）。标题样式已由脚本设置，目录可自动识别。`--toc` 生成的分节已把正文页码重编为从 `body_start_at` 开始、前置节按 `front_numbering` 处理，手工插目录时需自己在 Word 里分节并设页码起始值。
4. **更新域**：`Ctrl+A` 后按 `F9`，或右键目录 → 更新域 → 更新整个目录；确认目录页码与正文一致。脚本生成的目录域在首次打开时是空的，不更新就看不到条目。
5. 检查页眉（项目名）与页脚（`- 1 -` 页码）是否完整，封面页是否按需隐藏页眉页脚（`different_first_page` 由 profile 控制，默认 false）。
6. **另存 PDF**：文件 → 另存为 → PDF（标准），不要用第三方打印驱动。
7. 重新生成 docx 会覆盖手工内容：**docx 每重出一次，封面、目录域、PDF 都要重做一次**。

## 五、成品核查命令（已实测）

```powershell
# docx 页面尺寸与页边距（上/下/左/右，cm）
python -c "import docx,sys; s=docx.Document(sys.argv[1]).sections[0]; print('%.2f x %.2f cm' % (s.page_width.cm, s.page_height.cm), 'margins %.2f/%.2f/%.2f/%.2f' % (s.top_margin.cm, s.bottom_margin.cm, s.left_margin.cm, s.right_margin.cm))" "docs/选题报告/选题报告.docx"

# docx 内嵌图片数（必须排除 word/media/ 目录项，否则会多 1）
python -c "import zipfile,sys; z=zipfile.ZipFile(sys.argv[1]); print(len([n for n in z.namelist() if n.startswith('word/media/') and not n.endswith('/')]))" "docs/功能分析说明书/功能分析说明书.docx"

# PDF 页数（用标准库正则，本机无 pdfinfo）
python -c "import re,sys; print(len(re.findall(rb'/Type\s*/Page[^s]', open(sys.argv[1],'rb').read())))" "docs/功能分析说明书/功能分析说明书.pdf"

# PDF 页面尺寸：A4 应为 595 x 842；612 x 792 表示 Letter
python -c "import re,sys; m=re.findall(rb'/MediaBox\s*\[([^\]]*)\]', open(sys.argv[1],'rb').read()); print(m[0] if m else 'none')" "docs/功能分析说明书/功能分析说明书.pdf"

# PDF 首页文本（确认封面存在）
pdftotext -f 1 -l 1 "docs/选题报告/选题报告.pdf" -
```

2026-11-10 对本仓库现有成品的实测结果：

| 文件 | 页面尺寸 | 页边距(上/下/左/右 cm) | 内嵌图片 | 表格 | PDF 页数 | PDF 页面 |
| --- | --- | --- | --- | --- | --- | --- |
| docs/选题报告/选题报告.docx | 21.59 × 27.94 cm | 2.54/2.54/3.17/3.17 | 1（封面图） | 1（封面信息表） | 7 | 612 × 792 |
| docs/功能分析说明书/功能分析说明书.docx | 21.59 × 27.94 cm | 2.54/2.54/3.17/3.17 | 7（6 张正文图 + 1 张封面图） | 29（28 张三线表 + 1 张封面信息表） | 32 | 612 × 792 |
| docs/竞品分析报告/竞品分析报告.docx | 21.59 × 27.94 cm | 2.54/2.54/3.17/3.17 | 52（53 个 media 条目含 1 个目录项） | 14 | 77 | 未测 |

2026-11-10 实测：Skill 版脚本转换 `word-doc-pipeline/examples/示例文档.md` 得 A4（21.00 × 29.70 cm）、页边距 2.54/2.54/3.18/3.18 cm、页眉正常；`check_docx.py` 对示例 docx 退出码 0，对旧成品 `docs/功能分析说明书/功能分析说明书.docx` 退出码 1（页面为 Letter、页脚缺 PAGE 域）。结论：现有 docx 与 PDF 都是 **Letter**，与规范 A4 不符，是旧脚本未设页面所致；Skill 版输出 A4（PDF 应为 595 × 842），迁移后仍须用上面的命令复核。核对表格数时注意 docx 内还有一张封面信息表，不要与正文三线表混算。

## 六、字体依赖与跨机器风险

- python-docx 只写入字体**名称**，不嵌入字体文件；渲染依赖打开文档的机器。
- Windows 自带宋体、黑体，正常；macOS/Linux 缺这两种字体时会静默回退到其他中文字体，字号与行距观感改变，但不报错。
- 本机实测缺 **仿宋_GB2312、楷体_GB2312、方正小标宋简体**（注册表 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Fonts` 无条目）。profile 的 `[fonts.fallback]` 给出替换链（如 `仿宋_GB2312 → 仿宋 → FangSong → 宋体`），`md2docx.py` 生成时按链取第一个已安装字体并在 stderr 打印替换提示，**不中断转换**；`profile.py --check` 也会列出缺失项。公文、学位论文这类强依赖特定字体的文档，替换后字形不等价，正式提交前必须在装有该字体的机器上复核。
- 检查中文字体不能只看 `run.font.name`（只反映西文字体）：中文名写在 `w:rPr/w:rFonts/@w:eastAsia`。已实测本项目 docx 的一级标题 `eastAsia=黑体`、正文样式为 Times New Roman + 宋体。
- 换 Word 版本可能改变目录域、表格边框的默认渲染；WPS 的域与三线表支持差异较大，**未实测，须先在实际提交环境打开检查**。

## 七、已知坑

| 编号 | 现象 | 原因 | 规避 |
| --- | --- | --- | --- |
| K1 | 页面是 Letter 而不是 A4 | python-docx 新建文档默认 Letter（21.59 × 27.94 cm），旧脚本未设置 | Skill 版脚本已设 A4 + 页边距；换脚本/换工具后必须实测页面尺寸 |
| K2 | docx 缺图但转换"成功" | 图片路径不存在时脚本只打印警告并跳过，不中断 | 转换后核对图片数是否等于 md 引用数（+ 封面图） |
| K3 | 图片被裁切/显示不全 | 固定 22 磅行距放不下行内图片 | 图片段落必须用 1.5 倍行距（脚本自动处理，改脚本时勿丢） |
| K4 | 表格无法合并单元格、单元格内不能换行 | python-docx 能力限制 | 在 md 层规避：拆表、把多行内容改成短语 |
| K5 | 换电脑后字体、版式变形 | 字体不嵌入，依赖系统字体 | 交付前在目标机器打开复核 |
| K6 | 图片数比实际多 1 | Word 另存的 docx 含 `word/media/` 目录项 | 统计时过滤 `n.endswith('/')` |
| K7 | 重新生成后封面、目录、PDF 全丢/过期 | 脚本不处理封面目录，且覆盖 docx | 每次重出 docx 后重做手工步骤并重出 PDF |
| K8 | 中文路径下命令失败/中文乱码 | 未加引号或工作目录不对；md 非 UTF-8 编码 | 在项目根目录执行，路径一律加引号；md 保存为 UTF-8（无 BOM） |
| K9 | 目录页码错误 | 只插目录未更新域 | `Ctrl+A` + `F9`，或右键更新整个目录 |
| K10 | 表格数对不上 | docx 表格对象含封面信息表 | 以 md 表格数为基准，或看 `check_docx.py` 输出 |
| K11 | 改了脚本里的排版值却没生效 | 排版常量已挪进 profile，脚本只剩默认值兜底 | 改 `profiles/*.toml`，用 `profile.py --show` 确认实际生效值 |
| K12 | 校验报一堆差异，文档看着没问题 | 转换与校验用了不同 `--profile` | 两条命令都传同一个 profile；`check_docx.py` 输出首行会打印所用 profile |
| K13 | 文档字体名是「宋体」但字形不对 | 本机缺 profile 里指定的字体（如仿宋_GB2312），走了 fallback 链 | 看转换时的 stderr 替换提示；在装有该字体的机器上复核 |

## 八、迁移到新项目

复制与放置建议：

```text
<目标项目>/
  scripts/            <- 复制 profile.py、md2docx.py、check_md.py、check_docx.py、build_docs.py
  profiles/           <- 复制 ug-thesis-bit.toml（+ 需要的其他类型 .toml）
  references/         <- 复制本组规范（也可放 Skill 目录，不建议放 docs/ 下）
  docs/<文档类型>/     <- 各文档的 .md 与 images/ 子目录
```

不要把 `references/` 放进 `docs/`：`build_docs.py` 遍历 docs 时可能把规范文档也当成品转换。

迁移后必须修改/确认的参数：

| 参数 | 本项目取值 | 修改位置 |
| --- | --- | --- |
| 页眉项目名 | ChronoMed-Safe 慢病智能用药管理与风险预警系统 | 命令 `--project`、`build_docs.py` 调用处 |
| 文档类型目录 | 选题报告、功能分析说明书…… | docs/ 目录结构；`build_docs.py` 的 docs 入参 / `--include` |
| 图片目录与命名 | `<文档目录>/images/figX-Y.png` | md 中的图片引用 |
| 排版 profile | 默认 `ug-thesis-bit`；技术文档 `tech-doc` | 命令 `--profile`；新类型在 `profiles/` 新增 .toml |
| 字体方案 | 宋体/黑体/Times New Roman；三号/小三/小四/小五 | profile 的 `[body]`、`[[headings]]`、`[figure]`、`[table]` 段 |
| 页面与行距 | A4；上下 2.54 cm、左右 3.18 cm；固定 22 磅 | profile 的 `[page]`、`[body.line_spacing]` |
| 输出目录 | 与 md 同目录、同名 | 转换命令的输出参数 |
| 页码格式 | `- 1 -` 居中 | profile 的 `[header_footer.page_number]` 段 |

## 九、需实测项（本文未断言）

- WPS 中目录域、页码域、三线表边框的实际效果；Word 2016 / 2019 / Microsoft 365 的目录更新与 PDF 导出差异（均需在目标机器打开验证）。
- 无宋体/黑体环境（macOS、Linux、精简 Windows）下的替代字体与版式。
- A4 成品 PDF 的 MediaBox（应为 595 × 842）：本机无自动转 PDF 流程，需在 Word 另存后按第五节命令抽查。
- `build_docs.py` 全量真实转换（非 `--dry-run`）的耗时与汇总格式（尚未对 docs 执行，避免覆盖现有成品）；`check_docx.py` 已重写为 profile 驱动，覆盖页面/边距/页眉页码/图片宽度/三线表/正文与标题字体字号行距/目录域，但各分支只在 `examples/示例文档.md` 的 ug 与 tech-doc 两版输出上验证过，未覆盖全部文档类型（如公文、学位论文的镜像页边距、装订线、奇偶页页眉）。
